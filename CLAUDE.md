# Jabhouy

Flutter app for a small shop: inventory, customer loans, and bank-notification income tracking, offline-first.
Read [ARCHITECTURE.md](ARCHITECTURE.md) before changing structure; [docs/ARCHITECTURE_RESTRUCTURE.md](docs/ARCHITECTURE_RESTRUCTURE.md) records why it is shaped this way.

## Commands

The Flutter SDK is pinned by FVM (`.fvmrc`, 3.47.1). Prefix plain `flutter`/`dart` with `fvm`.

```bash
fvm dart run melos run analyze   # whole workspace; errors fail
fvm dart run melos run test      # dart test for core/sync, flutter test for the rest
fvm dart run melos run gen       # build_runner wherever it is a dependency
fvm dart run melos run run:dev   # also run:stg, run:prod, build:prod
```

A single test: `fvm flutter test test/loaner/loaner_model_test.dart`, or `cd packages/jabhouy_sync && fvm dart test`.
Translations live in `packages/jabhouy_l10n/lib/src/arb`; `fvm flutter gen-l10n` inside that package regenerates them.

The analyzer baseline is 3 issues and zero errors, all in `lib/home/` and `lib/app/constant/app_flavor.dart`.
Anything beyond those is new.

## Structure rules

- Packages under `packages/` never import `package:jabhouy/`. `test/architecture/package_independence_test.dart` fails if one does.
- `jabhouy_core` and `jabhouy_sync` stay pure Dart: no Flutter import, tests under `dart test`.
- A feature is `ui/` → `data/` (repository, `db/`, `api/`), plus `logic/` only for use cases that merge repositories or carry real rules. `logic/` imports no Flutter and no Drift, checked by `test/architecture/logic_layer_test.dart`.
- A bloc talks to a repository or use case, never to a Drift table or `ApiService`.
- Clean architecture applies inside `jabhouy_sync` only. The rest of the app uses the lighter layering above; this is settled.
- Only shop is a feature package. Do not extract others without being asked.

## Writing data

- Writes go to Drift first, then `SyncEngine.enqueue`, then drain if online. Never call the API from a bloc or repository write path directly.
- A synced entity needs a `SyncEntityType`, a DAO, a `FeatureSyncAdapter`, and an entry in the `AdapterSyncTransport` list in `lib/app/injection/dependency_injection.dart`.
- Adapters re-read the row and build the request body on every attempt. Keep it that way: it is how a queued job recovers after a client-side fix.
- New code returns `Result<T>` (`Ok`/`Err`). `ApiResponse` remains only in auth, profile and one file in `lib/app`.
- Date-only API fields use `DateTime.toIsoDate()` from `jabhouy_core`, which keeps the local day. Loans' `createdAt` is one.
- Loan JSON nests the customer (`"customer": {"id": …}`) with no flat `customerId`.
- Schema changes: edit `AppDatabase` in `jabhouy_core`, bump `schemaVersion` (7 now) with a migration, then `melos run gen`.

## Generated code

- `copyWith` is generated by `copy_with_extension`: annotate with `@CopyWith()`, add the `part` line to the library root (the bloc file, for bloc states), run `melos run gen`, and commit the `.g.dart`. CI does not generate.
- Generated `copyWith(x: null)` sets a nullable field to null; leaving `x` out keeps it. The analyzer's `avoid_redundant_argument_values` hint on `syncMessage: null` is a false positive; removing the argument is a bug.

## Feature flags

- Read flags through `getIt<FeatureFlags>().isEnabled(Feature.x)`, never `bool.fromEnvironment` directly.
- Adding one: a `Feature` value, a case in `BuildTimeFeatureFlags.isEnabled`, and a key in every `config/features/<flavor>.json`. A missing define is off.
- Income is off in production. Code that reads `IncomeBloc` outside `lib/income` must cope with it being absent.
- Every run and build passes `--dart-define-from-file`; the melos scripts, fastlane lanes and `.vscode/launch.json` already do. Patrol commands do not yet.

## Conventions

- Import feature barrels (`package:jabhouy/loaner/loaner.dart`) rather than deep paths, except where a comment explains a deep import keeps Flutter out of `logic/`.
- Nested routes receive blocs and models through GoRouter `extra` maps. Reuse the keys `AppRouter` reads: `shop`, `category`, `customerBloc`, `loanerBloc`, `incomeBloc`, `signoutBloc`, `existingItem`, `existingLoaner`, `activeCategory`, `onAdd`.
- Some income actions are guarded by `kReleaseMode` on purpose. Keep those guards.
- `iPad (wireless)` belongs to a tester. Never choose it as a run target.
- Keep answers short and ask one clarifying question at a time.
